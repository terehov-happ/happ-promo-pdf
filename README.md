# Аналітичний звіт розмов — веб-версия и PDF

Отчёт HAPP по разбору коммуникаций: 2 000 разговоров (1 000 звонков и 1 000
переписок) клиента AVELON за 1–31 августа 2026. Один и тот же документ работает
как страница по ссылке и как PDF — второе получается из первого через
`@media print`, отдельной вёрстки под печать нет.

Язык документа — украинский (`lang="uk"`). Комментарии в коде — русские, как и
во всём проекте.

```
report/
  index.html            вся разметка и все числа
  assets/report.css     токены, компоненты, печать
  assets/report.js      вскрытие шкал, подсветка раздела, печать
  assets/happ-logo.svg  логотип (и -white для обложки), happ-symbol.svg — favicon
scripts/make-pdf.ps1    сборка PDF без участия человека
scripts/serve.py        локальный сервер для замеров и правки стилей
dist/happ-report.pdf    результат сборки
```

## Как посмотреть

Открыть `report/index.html` в браузере. Сборки нет: это статика без зависимостей,
единственный внешний запрос — Inter и Host Grotesk с Google Fonts (без них
страница печатается системным шрифтом, но не ломается).

Если правите стили — лучше через `python ./scripts/serve.py`
(http://127.0.0.1:8777). `python -m http.server` не шлёт `Cache-Control`, Chrome
применяет эвристическое кэширование и после правки CSS отдаёт старый файл; здесь
заголовок задан явно. Тот же сервер нужен для замера высот разделов: из `file://`
браузер не отдаёт `cssRules`.

Для отдачи по ссылке — выложить папку `report/` на любой статический хостинг как есть.

## Как получить PDF

**Из браузера.** Кнопка «Завантажити PDF» — в плавающем лаунчере внизу по
центру и в обложке. Открывает диалог печати; в нём — «Сохранить в PDF». Перед
печатью скрипт раскрывает все шкалы: те, что не попали в кадр, на бумаге вышли
бы нулевыми.

**Скриптом.**

```powershell
pwsh ./scripts/make-pdf.ps1
pwsh ./scripts/make-pdf.ps1 -Out dist/happ-report-august.pdf
```

Скрипт находит Chrome или Edge сам (`-ChromePath` — если лежит нестандартно) и
печатает через `--print-to-pdf`. Сейчас на выходе A4, 10 страниц, ~900 КБ.

## Откуда взяты стили

Отчёт следует дизайн-языку лендинга — `happ-landing-next/DESIGN.md`. Это
первоисточник, а не «вдохновение»: значения ниже скопированы оттуда, и при споре
правым считается лендинг.

| Что | Значение лендинга |
| --- | --- |
| Страница | белая насквозь; чередования фона по секциям нет |
| Карточка | заливка `#fafafa`, рамка `#e5e7eb`, радиус **20px**, **без тени** |
| Иллюстрация в карточке | на белой плите поверх серой (`.card__body--panel`) |
| Зазор между карточками | 12px — «карточки стоят плотно» |
| Ритм секции | `py-24` (96px), гаттер `md:px-[130px]`, шапка ↔ контент 48px |
| `SectionHeading` | центрированная колонка: eyebrow → Host Grotesk 36/44 → подзаголовок |
| Заголовки | Host Grotesk, вес 400/500, **никогда не bold**, отрицательный трекинг |
| H3 карточки | Host Grotesk 20/30 (а не мелкий жирный Inter) |
| Кнопки | радиус 12px; синяя — в шапке и на небе, тёмная `#0a0d12` — на светлом |
| Внутренняя тень кнопки | `inset 0 0 0 1px rgba(10,13,18,.18), inset 0 4px 4px rgba(255,255,255,.25)` |
| Небо | `#1a62f5` + полосы + радиальный фейд в белый; единственное «богатое» место |
| Стекло | только на небе: `bg-white/10` + рамка `white/30` + `blur(6px)` |
| Шапка | плавающая пилюля поверх неба, радиус 26px (ровно половина высоты, не `999px`) |

Остальное — из `platform-ui`, откуда взяты вещи, которых на лендинге нет:

| Источник | Что взято |
| --- | --- |
| `platform-ui/src/styles.css` | серая рампа `gray-25…950`, статусные рампы, `--ease-out-strong` |
| `redesign/pages/analysis/analysis-chart-placeholder.tsx` | столбцы на CSS через `scaleY`, без чарт-библиотеки |
| `redesign/pages/analysis/analysis-types.ts` | тон оценки по шкале `scoreToTone()` (80 / 60 / 40) |

Всё переписано на чистом CSS с этими же значениями: странице не нужны ни React,
ни Tailwind, а печать надёжнее, когда классы не генерируются на ходу.

**Шапка лежит на небе, а не над ним.** `.topbar` — `fixed`, а не `sticky`:
`sticky` участвует в потоке и отодвигает герой вниз, поэтому пилюля оказывалась
на белой полосе над градиентом. Вне потока она ложится поверх неба — так же, как
на лендинге, где плита неба спозиционирована абсолютно и хедер естественно
оказывается над ней. Пилюля обжимает содержимое, а не тянется на всю колонку:
пока справа стояла кнопка, ширина 1180px держала три группы по краям; после
переезда кнопки в лаунчер осталось две, и между подписью и навигацией зияла
пустая треть.

**У героя тот же гаттер, что у секций.** Отступы входят в `max-width`
`.hero__inner`, и они должны совпадать с отступами `.section` — 24px на мобиле,
130px от 900px. Пока у героя было 48px, полоса контента расходилась на всех
экранах уже 1440px: панель фактов шла на 1180px, а карточки разделов — на 1017,
и панель выезжала за колонку остального документа на 160px.

**Единственное действие документа — в лаунчере.** Скачивание PDF раньше стояло
тремя одинаковыми кнопками: в шапке, в обложке и в подвале. Осталось две — в
обложке (там это часть первого экрана) и в плавающей пилюле внизу по центру,
собранной по рецепту агент-виджета лендинга (`FloatingWidget.tsx`): белая
капсула, рамка `#e9eaeb`, тень `0 2px 2px rgba(0,0,0,.08), 0 12px 8px
rgba(0,0,0,.05)`, внутри всё `rounded-full`. Лаунчер прячется, пока обложка в
кадре, — иначе на первом экране стояли бы две одинаковые кнопки рядом. Скрытое
состояние обусловлено классом `.js`: без скрипта лаунчер просто всегда видим, а
не пропадает совсем. Подвалу добавлен нижний отступ, чтобы пилюля не легла на
его текст.

### Сознательные отступления от лендинга

**Небо глубже.** У лендинга оно к середине почти белое; здесь та же плита должна
работать ещё и полностраничной обложкой PDF, поэтому насыщенность выше. Отсюда
же второе отступление: основная кнопка на небе белая, а не синяя, как требует
правило выбора кнопок, — синяя на этой плите превращается в пятно чуть темнее
фона.

**Фейд обложки в печати — линейный.** Радиальный рассчитан на широкую плиту
экрана; на вертикальном A4 тот же эллипс растягивается на весь лист, белое
начинается с середины, и белый заголовок садится на белое. В `@media print`
градиент заменён линейным: синее до 58%, белое с 78%.

**Заголовки разделов по левому краю в печати не выравниваются заново.** Они
центрированы, как на лендинге, и на полосе 186mm это читается.

## Что важно знать при правках

**Числа лежат в разметке, не в скрипте.** Страница читается и печатается с
выключенным JS. Свёрнутые состояния шкал обусловлены классом `.js`, который
ставит инлайновый скрипт в `<head>`: без него шкалы нечему развернуть, и отчёт
показывал бы нулевые оценки вместо настоящих.

**Host Grotesk не знает кириллицы** — только latin и latin-ext. Заголовки набраны
`--font-hero`, где вторым в стеке стоит Inter, поэтому украинский текст в них
приходит из Inter, а латиница и `₴` — из Host Grotesk. В смешанной строке
(`$49 на місяць`) видны обе гарнитуры; это цена того, что шрифты те же, что на
лендинге.

**Оранжевого бейджа нет.** По правилу цвета лендинга акцент один — синий, а
цветной текст допустим в трёх ролях: eyebrow, инлайн-ссылка, бейдж. Оранжевый
был здесь третьим акцентом, `warning-700` — это коричневый, и рядом с красным он
читался как выцветший красный. Вдобавок тон ничего не значил: «720 діалогів» и
«14 хв на відповідь» в разных разделах стояли то оранжевыми, то красными. Все
такие бейджи сведены к `pill--down`, «на місяць» — к `pill--neutral`, жёлтая
выноска `note--warn` убрана. Оранжевый остался там, где он данные: столбцы часов
без дежурного (`--warning-500`) и ключ их легенды.

**Бейджи — вариант Untitled UI с рамкой:** заливка `-50`, рамка `-200`, текст
`-700`. Плоские заливки без рамки при здешней плотности читались как размытые
пятна. Осветлить текст до `-600` нельзя: красный на `error-50` даёт 4,44:1, ниже
порога AA; кромку даёт рамка, а не более светлый текст. Ключ легенды графика
(`pill--key`) — нейтральный чип с точкой цвета ряда: два залитых бейджа спорили с
самими столбцами.

**Шкала `.criterion` бывает без оценочного тона.** В разделах тем, сегментов и
потенциала она показывает доли, а не качество: главные строки — брендовые,
остальные — `--muted` (серые). Красный и жёлтый там значили бы «плохо», чего в
доле процента нет. Оценочные тона (`--high` / `--good` / `--medium` / `--low`)
остаются в разделе качества и в причинах отказа.

**Раздел — страница.** `break-before: page` стоит на каждом `.section`, и это
работает только потому, что печатная типографика ужата под полосу: самый высокий
раздел (двенадцать тем со сводкой) занимает 258mm из 269mm доступных, самый
низкий (время) — 155mm. Проверять высоты после правок нужно обязательно: раздел,
переросший 269mm, уронит хвост на следующую страницу, и та уйдёт под одну
карточку. Мерить удобно так — открыть страницу с локального сервера (с `file://`
браузер не отдаёт `cssRules` — например `python ./scripts/serve.py`),
переключить `@media print` на `all` и снять высоты `.section`:

```js
for (const sheet of document.styleSheets)
	for (const r of sheet.cssRules)
		if (r.media?.mediaText.includes('print')) r.media.mediaText = 'all';

document.querySelectorAll('.section').forEach((s) =>
	console.log(s.id, Math.round(s.getBoundingClientRect().height / (96 / 25.4)), 'mm')
);
```

Сквозной поток экономил страницу-другую, но платил разорванными карточками:
строка приходила на следующую страницу без верхней рамки и без заголовка, над
которым она стоит, — это читается как сбой печати, а не как продолжение.

**`break-inside: avoid` не ставится на высокие `.card`.** Карточки-контейнеры
двенадцати тем и шести критериев выше половины страницы, и запрет разрыва их не
сжимал, а выталкивал целиком, оставляя предыдущую страницу пустой. Запрет живёт
на том, что заведомо влезает: `.kpi`, `.step`, `.finding`, `.criterion`, `.loss`,
`.quote`, `.check`, `.bars`, плюс парные карточки `.grid--2 > .card` и карточки
правого рельса `.grid--wide-left .card--pad`.

**Печатный кегль строки критерия задан отдельно.** Экранные 14px названия и
12,5px пояснения поставлены под 14px основного текста; при печатных 10,5px они
читаются как подзаголовки и раздувают список из двенадцати строк на треть
страницы. В печати вся строка приведена к 11,5/10px, отступ — 6px вместо 14.

**Разряды чисел склеены `&nbsp;`.** `2&nbsp;000`, `102&nbsp;100&nbsp;₴`,
`14&nbsp;хв`. Без этого перенос рвёт число посередине, и строка заканчивается на
«1 000 дзвінків і 1», а следующая начинается с «000 переписок». В документе, где
числа — единственное содержание, это дороже, чем кажется.

**Полоса печати — около 700px**, то есть уже узких брейкпоинтов страницы. Поэтому
`@media print` заново задаёт то, что мобильные правила успели схлопнуть: четыре
KPI в ряд, две и три колонки в сетках. И наоборот — ужимает то, что на экране
влезало: в карточках `grid--2` трек критерия сжат с 168px до 64, иначе под
название остаётся 90px и текст рассыпается в вертикальную полоску. Проверять
правки вёрстки нужно и в печати тоже — экран здесь не показатель.

**Двадцать четыре столбца в `.bars--hours`.** Базовый `.bars` рассчитан на
шесть колонок с зазором 12px; для суток зазор и подписи ужаты, а на печати —
ужаты ещё раз, иначе трёхзначное значение над столбцом переносится в две строки.
Часы без дежурного в чате (00–08 и 18–23) покрашены `--warning-500`; пик 11:00
остаётся брендовым.
